## 准备和安装

1. 保存工作，通过原应用正常退出入口完全退出，确认没有正在生成或保存的会话。不要仅凭窗口隐藏认定退出，也不要强制结束真实会话。
2. 在应用退出后备份当前桌面数据到本机。不删除全局 `.dsh`、独立 Sub2API、账号或密钥，不上传这些内容。
3. 对实际安装包位置执行 `Get-FileHash -LiteralPath '安装包的绝对路径' -Algorithm SHA256`，与上表核对。哈希不匹配立即停止。
4. 运行已校验安装器。社区包 `Authenticode: NotSigned`，若系统安全策略阻止，保留提示并停止，不关闭安全软件或绕过策略。安装器提示仍有进程或探测不确定时，正常退出后再试，不强制结束同名程序。
5. 从正常安装入口启动，确认版本为 0.6.0。通过“添加 API Key”检查中文界面及空密钥禁止保存，再点“稍后配置”进入工作台，检查设置可以打开。不要输入密钥或发起模型请求。

## 两轮原生操作

以下内容在两次分别启动的应用中完整执行，分别记录第 1、2 轮。准备一个不含文件的中文空格目录，例如 `C:\DSH-验收\中文 测试目录`，不要选择真实项目、个人资料或配置目录。

1. 使用工作台打开/选择文件夹入口。确认出现可交互的 Windows 原生文件夹对话框，没有 `win32 folder dialog worker exited before reporting a result` 错误。网页目录列表不算本项。
2. 先取消，确认工作台可用、无错误且没有误选目录；重新打开并选择上述中文空格目录，确认路径无乱码、实际使用的目录正确。再重复一次取消/选择，检查不卡死。
3. 在工作台使用原生“应用 → 退出”，按正常提示确认。观察任务管理器，确认本次主进程及看门狗自行结束；窗口消失、隐藏托盘或欢迎页关闭不能替代此项。有无法归属的同名进程时，不要结束它，记为无法确认。
4. 进程消失后继续观察至少 7 秒，不主动启动程序。记录实际无重启观察时长（7000–300000 毫秒）。随后从正常入口重新打开，确认可进入中文界面/工作台且没有恢复循环。
5. 完成第 1 轮后，在新启动的程序中完整重复以上操作，完成第 2 轮。任何错误、卡住或无法确认均保留为失败/未测试，不补造通过。

首次 45 秒健康观察之后还需完成约 1 GB 的稳定副本复制和摘要核验；仅等待 45 秒不代表可回退缓存已完成。没有完整且通过校验的副本、或系统同时阻止当前版与副本启动时，只会有界停止并保留记录，不能承诺所有故障都能自动恢复。不需要用户再次注入崩溃。

## 记录和只读核验

将 [0.6.0 模板](stable-readiness-0.6.0.example.json) 的副本保存为 `.official-build/stable-readiness.json`。若已有旧记录先保留，不直接覆盖。仅将实际确认成功的六个项目填为 `pass`；失败为 `fail`，未执行或不确定保持 `not-tested`。每轮填写实际完成的 ISO UTC 时间（含毫秒，`Z` 结尾），第二轮晚于第一轮；填写进程消失后的实际无重启时长。只有亲自确认记录真实才设置 `operatorConfirmed:true`。

项目根目录执行 `npm run qualify:stable:automatic` 和 `npm run qualify:stable`。它们只检查绑定及记录，不启动桌面、不调用模型、不发布 GitHub，也不改变更新通道。未验收模板必须被拒绝；核验通过也不是原生点击的自动证明或发布授权。

原始证据留在本机。公开材料不含账号、密钥、个人绝对路径、会话、进程命令行或恢复控制令牌。另有生产依赖 fflate 的中等级 ZIP64 拒绝服务风险，避免处理不可信压缩包；原生验收通过也不能自动消除该风险。详见 [测试报告](test-report-0.6.0.md)。
