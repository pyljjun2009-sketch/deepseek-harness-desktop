# ADR 0008：本地 Host 使用系统分配的端口

## 状态

已采用；2026-10-10 新载荷的并行实例、完整安装与真实崩溃回退验收通过。整体稳定发行仍需正常退出及原生目录交互验收。用户明确要求稳定优先，本变更仅处理同机端口冲突，不扩展远程访问。

## 背景与非功能要求

2026-10-10 完整安装器两轮验证通过后，真实恢复与界面测试并行运行，确认锁定的官方 Host 使用固定 `19387`。独立数据槽并不能隔离系统 TCP 端口，第二个 Host 以 `EADDRINUSE` 失败。旧稳定副本仍使用同一端口，回滚无法排除该环境故障。

要求：不因无关进程占用某个固定端口而启动失败；只监听本机回环地址；保留认证 URL、官方 IPC、数据槽与恢复约束；不终止占用端口的其他进程，不对网络暴露服务。

## 决策

官方 Host 的唯一 CLI 默认端口由 `19387` 改为 `0`，让操作系统在 `listen` 时直接选择可用端口。保留官方 WebServer 的 `127.0.0.1` 绑定及认证机制。实际端口仍通过现有 `ready` IPC 中的认证 URL 传递给桌面壳，HTTP、WebSocket 与健康探针继续使用该 URL。

```text
Host listen(0, 127.0.0.1) → OS 分配端口 → ready URL → 桌面转发 / WebSocket / 健康探针
```

变更纳入 official-overlay.patch，重新编译和打包 Host、生成包集、更新该 tarball 的冻结锁完整性、重做完整运行时摘要和候选包，再重复安装与真实恢复资格测试。禁止直接修改已密封运行时。显式用户插件配置仍可能覆盖默认端口；本决定不自动改写用户配置。

## 取舍与备选

- 不先扫描“空闲端口”再绑定，避免扫描与真正 listen 之间的竞争。
- 不结束占用 `19387` 的程序，避免影响用户其他应用。
- 不仅在 QA 根 patch 中覆盖端口，否则测试规避了产品默认行为，正式安装仍有风险。
- 端口在重启后可能不同；直接依赖固定内部端口的非官方脚本需要改用应用提供的入口。正常桌面流量使用 ready URL，无需用户知道端口。
- 本变更不消除防火墙/安全软件阻止全部本机连接、磁盘损坏或无完整缓存等故障；恢复仍是有界而非无限保证。

## 验收

重新构建的 Host tarball、生产锁、包集与全树摘要一致；两个全新隔离实例同时通过本地认证健康检查，且真实三次崩溃回退、中文界面与完整安装事务重新验证。受固定端口冲突污染的上一轮缓存健康测试不计为通过。

实际结果：Host 默认端口门禁及实际源码壳 23/23；界面实例实际使用 65518，后续新实例使用 53280；与生产恢复资格并行时不再出现固定端口冲突。最终载荷三次异常退出、稳定缓存健康及自有进程清理通过，两轮隔离安装各 9947 个文件完全一致。没有扩大监听地址或取消认证。

## 依据

固定官方源码 `apps/desktop-host/src/index.ts`、`packages/host/webserver/src/index.ts`、`packages/host/web-startup/src/index.ts` 和 `apps/desktop/src/host-process.ts`：WebServer 接受端口 0，ready URL 由实际 `ctx.webServer.port` 构造。
