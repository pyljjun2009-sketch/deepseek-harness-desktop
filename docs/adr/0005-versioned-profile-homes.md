# ADR-0005: 运行时与用户数据成对切换

## 状态

Accepted

## 背景

仅为 DSH 可执行文件保留候选槽和稳定槽并不足以保证回滚。新版 DSH 可能在启动时修改 profile、插件链接、配置或会话索引；旧版可执行文件即使存在，也未必能读取被新版修改的数据。官方 DSH 处于快速演进中，其 Desktop 设计也把运行时与壳作为一个版本单元；本项目为了允许运行时独立升级，必须承担额外的数据隔离与恢复责任。

## 决策

1. 捆绑运行时使用原有 `harness-home` 作为 `default` 数据槽。
2. 下载、CLI 烟测与真实 Web/HTTP 预检使用一次性空数据槽，不接触活动槽。只有预检通过才停止旧运行时。
3. 监督器停止现有 DSH 后，复制活动数据槽到 `profile-homes/slot-<version>-<uuid>`；不复制 DSH 自动生成的 `profiles/node_modules` 依赖投影。候选在副本中重新生成依赖链接，再运行配置烟测、启动及 45 秒观察。
4. 状态文件 v2 成对保存 `active/activeHomeId`、`lastKnownGood/lastKnownGoodHomeId` 和候选指针。激活、晋升、回滚都同时切换程序与数据。
5. 失败候选槽暂不自动删除，避免丢失候选期间产生的会话；稳定槽也不自动清理。未来清理策略必须排除所有状态指针并提供手动导出。
6. v1 状态读取时映射到 `default`；这不能追溯隔离过去已经写入该槽的旧版候选。

## 后果与取舍

- 回滚恢复的是升级前的数据快照；候选期间新增的数据仍在失败槽中，但不会自动合并。故障回滚的会话 RPO 不保证为零。
- 首次克隆会随会话规模增加磁盘占用与升级耗时。大数据目录可能造成升级失败；失败时保留现有运行时，不进行半切换。
- DSH 生成的依赖链接由候选 `--dump-config` 在副本中重建，避免 Windows 普通权限复制目录联接失败或保留旧路径。其他用户自建符号链接若无法复制，升级会失败并继续使用原稳定槽。配置烟测只能证明可加载，不能证明所有插件行为兼容；HTTP 和观察期继续承担后续验证。
- 同一桌面进程拥有单实例锁；升级克隆之前必须结束 DSH 写入进程。其他进程直接改写数据目录不在本决策的保证范围内。
- 长期留存旧槽含会话和凭据，用户需考虑本机磁盘加密和备份政策。

## 备选方案

- 共享一个 `DSH_HOME`：空间小，但旧二进制回滚不能撤销新版数据变更，拒绝。
- 原地复制覆盖旧数据：可能覆盖用户在失败候选期间产生的内容，拒绝。
- 永远绑定壳与运行时版本：最易证明兼容，也是官方 Desktop 的方向；本项目保留可选运行时升级，故选择隔离槽并明确降低兼容性保证。
