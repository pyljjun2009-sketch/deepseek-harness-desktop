# ADR 0010：固定官方包、同版本重构与版本化升级接口

## 状态

已采用；接口 v1 已实现并通过单元测试与实际 ASAR 成品验证。社区 0.6.0 已通过独立安装和真实恢复资格；原生交互及安全风险审阅仍待完成，不授权稳定晋升。

## 背景

用户要求根据 DeepSeek 官方升级包升级并预留后续升级接口。官方 Windows feed 已发布 0.2.1-rc.2，旧社区版本固定在 0.2.0-rc.2。官方应用和社区恢复版的身份、入口与数据约定不同，直接运行官方安装器不能保证保留社区恢复保障。稳定性、账号/数据隔离、可审计摘要和故障后保留旧版优先于无人值守追新。

## 决策

固定官方安装器的版本、来源、大小、SHA-512与对应源码提交；构建同版本社区恢复版。使用 v1 提供者分离检查、下载、校验和准备；现阶段不提供安装权限。真实消费者为开发 CLI 和基线构建器，默认不进行网络检查。已有桌面菜单继续使用固定社区更新源，新版官方支持的清单通道参数取代重复协调器补丁。

下载只接受固定官方 HTTPS 路径，拒绝重定向、额外认证字段和不匹配摘要；缓存以独占方式发布，不覆盖突然出现或损坏的文件。完整运行时和安装器须重新封闭、健康检查、隔离安装和崩溃测试，并完成人工原生对话框/菜单验收；失败则停止晋升而不改当前安装。

## 取舍

优点是官方包/源码同版本、升级准备可独立测试，且不会丢失社区恢复层。代价是不能直接无条件应用官方二进制更新，社区层需要重新构建、测试和审阅；多保留一个约 289 MB 的官方包作为校验输入。旧构建目录已迁移为跨盘链接，原有物理路径检查会保守拒绝；应在独立物理位置生成新测试资源，不放宽链接校验或修改用户现有目录。

## 备选方案

直接应用官方安装器省去社区构建，但改变应用和数据身份、绕过社区门槛，拒绝。只替换 CLI/runtime 会混合未经组合验证的壳与运行时，拒绝。仅预留空方法没有真实消费者和负例验证，拒绝。
