## 1. 准备、备份并安装

1. 确保当前没有模型生成、正在保存的会话、文件写入或重要任务。保存工作，通过现有应用的正常退出入口完全退出；仅关闭工作台窗口可能只是隐藏到托盘，不能据此认定已退出。
2. 在程序完全退出后，按当前安装实际使用的数据位置备份需要保留的桌面数据与会话。备份保留在本机，不上传到 GitHub。不要删除或修改全局 `.dsh`、独立 Sub2API、已有账号或密钥；本次候选不需要它们。
3. 在 PowerShell 中对实际下载位置运行以下只读命令，将结果与上表及发布页 `SHA256SUMS` 比较。替换示例中的安装包路径；不匹配时停止，不运行安装器。

   ```powershell
   Get-FileHash -LiteralPath 'C:\验收下载\DeepSeek-Harness-Desktop-0.5.0-x64.exe' -Algorithm SHA256
   ```

4. 运行已校验安装器。安装器如提示应用仍在运行或进程探测不可靠，应正常退出应用后重试；不要用强制结束进程来完成本操作单。安装器不会主动结束同名进程。
5. 从新安装的桌面入口启动，从应用版本信息或安装文件属性核对社区发行版本为 `0.5.0`。如版本无法确认，先记为“未测试/无法确认”，不要用旧版结果补填候选通过。

## 2. 中文界面与工作台入口

1. 检查欢迎页为中文。尚未配置凭证时，可打开 API 配置入口，确认空密钥不能保存，然后返回欢迎页；已有配置时不要清空、修改或公开其内容。不要输入真实 API 密钥、登录账号或发起模型请求。
2. 点击“稍后配置”进入工作台，打开设置并检查中文显示，再正常关闭设置。
3. 若实际界面没有预期入口、显示错误或无法进入工作台，记录为失败或未测试并停止晋升判断，不要通过开发者工具、脚本或隐藏接口模拟这些操作。

本轮操作只验证界面和本地流程，不验证真实 API 可用性、模型质量或 token 节省比例。

## 3. Windows 原生文件夹选择器

先在本机准备一个不含敏感文件的空测试目录，目录名包含中文和空格，例如 `C:\DSH-验收\中文 测试目录`。不要选择真实工作项目、账号配置目录或个人文档目录。第 3、4 节须在两次分别启动的应用中各执行一遍，记录为第 1、2 轮；不能把同一轮的操作重复填入两轮记录。

1. 在工作台使用打开/选择文件夹的可见入口，确认出现 Windows 原生文件夹对话框，而非应用中的网页目录列表。确认对话框可交互，且没有原先的 `win32 folder dialog worker exited before reporting a result` 错误。
2. 先点击原生对话框的“取消”。预期：对话框正常关闭，工作台保持可用，不报错，也不误选其他目录。
3. 再从同一工作台入口重新打开原生对话框。选择上述中文、带空格的空测试目录并确认。预期：工作台显示/使用所选目录；没有错误弹窗或路径乱码，也没有意外访问别的目录。
4. 再次打开选择器，重复一次取消与重新选择。预期：选择器不会卡死、提前退出或失去响应，工作台仍可操作。

只有真实可见的原生对话框及上述操作都确认成功，才可将文件夹验收记为“通过”。仅看到入口、点击网页目录浏览器或使用脚本代替原生对话框，均不算通过。

## 4. 工作台原生菜单退出与重新启动

1. 保持在工作台，保存可能产生的本地改动。通过桌面应用的原生“应用”菜单选择“退出”；出现确认提示时，按正常流程确认。
2. 用任务管理器观察本次应用进程是否自行结束。窗口消失或托盘隐藏本身不算通过；与本次实例对应的主进程、看门狗也必须不再运行。如果有无法归属的同名进程，不要结束它，记为无法确认。
3. 确认本次实例进程消失后，继续观察至少 7 秒，期间不要手动启动应用。记录实际完整观察时长，核验允许的范围是 `7000–300000` 毫秒。预期：无自动重启、无新窗口、无本次实例的新进程。
4. 再从正常桌面入口重新打开一次。预期：可以正常进入中文界面/工作台，无异常恢复循环。第 1 轮完成后，在这次重新启动的应用中完整重复第 3、4 节，完成第 2 轮；第 2 轮也须验证退出、进程消失、无重启观察和重新打开。

欢迎页关闭测试已经有独立的自动资格证据，但**关闭欢迎页不是工作台原生菜单退出通过**。关闭工作台窗口、强制结束进程、直接调用退出接口或模拟菜单，都不能替代本项。若正常退出卡住，请停止验收，先保留已脱敏的错误描述并联系维护者；不要强制结束真实会话来补造通过结果。

## 5. 恢复边界与验收记录

首次启动需要持续 45 秒本地认证 RPC 健康观察，此后还要完成完整稳定安装副本的复制和摘要校验。**仅等待 45 秒，不代表稳定缓存已经就绪**。约需额外 1 GB 磁盘空间；只有完整、已校验的稳定副本可用于自动回退。没有可用缓存、缓存损坏或系统同时阻止当前版与缓存启动时，会有界停止并保留恢复记录，不能承诺所有错误都自动恢复。

不要为了本机人工验收强制结束真实会话。真实崩溃恢复测试已在隔离资格环境单独执行；本操作单不要求用户再做破坏性故障注入。

首次安装/同版本替换与独立卸载是已有隔离自动资格证据，不要在人工表中写成自己执行过两轮安装和卸载。

### 本地记录与只读核验

1. 使用仓库中的 [记录模板](stable-readiness.example.json)，在本机保存副本为 `.official-build/stable-readiness.json`。已有副本时先保留原结果，不直接覆盖。模板中的候选身份、两个成品摘要、官方提交及自动报告引用已绑定本次候选；换任何安装包后，都必须重新核对摘要、重新生成对应报告和模板，不能只改版本号沿用旧结果。
2. 在两轮实际操作结束后，分别填写 `manual.rounds` 的对应轮次。`nativeFolderPicker`、`nativeFolderCancel`、`nativeFolderChineseSpacePath`、`workspaceMenuQuit`、`processStopped` 和 `relaunch` 只在相应真实操作确认成功后填 `pass`；失败填 `fail`，未执行或无法确认保留 `not-tested`。不要提前填写通过。
3. 每轮 `testedAt` 填实际完成时间，使用规范的 ISO 8601 UTC 格式，包含毫秒并以 `Z` 结束；第 2 轮的时间必须晚于第 1 轮。`noRestartObservedMs` 填进程消失后实际连续观察且无重启的时长，必须为 `7000–300000` 毫秒；不应把应用操作时间、退出等待时间或两轮时长相加填入此项。
4. 保持 `platform: "win32-x64"`、`method: "native-visible-interaction"`。只有操作人亲自确认以上记录真实，才把 `operatorConfirmed` 改为 `true`；不得代替未完成的操作确认。无需填写个人姓名、个人路径或截图链接。
5. 在项目根目录运行只读核验命令：

   ```powershell
   npm run qualify:stable:automatic
   npm run qualify:stable
   ```

   前者仅检查绑定同一成品的自动资格证据，不能代替人工验收；后者同时检查本地记录中的两轮人工门槛。命令不操作真实账号、不调用模型，也不自行发布 GitHub Release 或更改 `latest`。退出非零、失败或缺项均不能视为稳定资格通过，修改问题后需重新执行对应真实操作并重新核验，不能为了让命令通过而改写事实。

人工记录属于操作人的自述确认，不是密码学签名，也不是对原生交互的自动证明；核验通过只说明记录与规定的绑定条件一致。本次候选分支更新后的 CI 工作流仅构建、执行资格检查并保存 artifact，不因标签或此项通过自动发布到稳定通道。该工作流尚未合并到 `main`，也未改变历史引用对应的规则，不能据此声称仓库所有标签的自动发布已全局关闭；稳定主分支的工作流仍需后续 PR 审核，不做未经验收的稳定晋升。

公开记录只保留白名单结果和候选绑定值。不要填写个人绝对路径、账号、密钥、完整原始日志、进程命令行或恢复控制令牌；截图公开前也应遮盖个人路径、会话内容和账号信息。原始诊断证据留在本机，确需提交时先由维护者确认安全范围。

本单完成或只读核验通过，都不构成发布授权，也不自动改写 GitHub Release、`latest`、签名状态或自动资格报告。维护者必须复核绑定同一候选的人工记录及自动证据，并取得稳定发布所需授权后，才可按稳定晋升规则单独决定是否晋升。**任何失败或未测试项，都不能以“继续”或自动测试通过来覆盖。**
